# ЛР3 — аренда электросамоката

Учебная реализация разделов III–IV методички для предметной области «Аренда электросамоката». Доменный слой и прикладной процесс не импортируют Flask. Репозитории хранят данные в памяти; после перезапуска контейнера данные сбрасываются.

## Запуск локально

```bash
python -m venv .venv
# Windows: .venv\\Scripts\\activate
# Linux/macOS: source .venv/bin/activate
pip install -r requirements.txt
python -m app.web
```

Для запуска через gunicorn:

```bash
gunicorn --bind 0.0.0.0:8000 --workers 1 --log-level info app.web:app
```

## Запуск в Docker

```bash
docker compose up --build
```

Проверка готовности: `GET http://localhost:8000/health`. Порт и уровень логирования задаются переменными `PORT` и `LOG_LEVEL`. В compose задан один worker и непривилегированный пользователь.

## Основные маршруты

- `POST /users` — создать клиента (`{"full_name":"Иван Петров","payment_data":"demo-payment-method"}`; `payment_data` опционален для учебного запуска).
- `GET /users/<id>` — состояние аккаунта и журнал событий.
- `POST /scooters` — создать самокат (`{"battery_percent":80}`).
- `GET /scooters/<id>` — текущее состояние самоката.
- `POST /rides` — создать бесплатную бронь (`{"user_id":"...","scooter_id":"..."}`). Возвращает ID поездки/брони.
- `GET /rides/<id>` — состояние поездки, допустимые в нём события и журнал доменных событий.
- `POST /rides/<id>/start` — начать поездку (проверка долга, состояния/заряда самоката, авторизация 300 ₽ и обе операции запуска).
- `POST /rides/<id>/pause` — пауза.
- `POST /rides/<id>/resume` — возобновление.
- `POST /rides/<id>/finish` — завершение после фото (`{"zone_allowed":true,"photo_received":true}`). Если `zone_allowed:false`, поездка остаётся активной/на паузе.
- `POST /rides/<id>/pay` — списание стоимости завершённой поездки.
- `POST /users/<id>/settle-debt` — попытка погашения долга.
- `POST /rides/<id>/operator-contact` — зафиксировать связь оператора с клиентом после отправки уведомления.
- `POST /internal/tick` — обработать таймеры; принимает необязательное `{"now":"2026-10-23T09:00:00Z"}`. Перевод времени назад запрещён.
- `GET /health` — health-check.

Внутренний `POST /internal/payment-outcome` включается только при `ENABLE_TEST_CONTROLS=true` и нужен исключительно для демонстрации исходов заглушки оплаты. В реальной интеграции его следует удалить/закрыть.

## Важные допущения и изменения модели ЛР2

1. Для краткосрочной брони добавлено состояние `reserved` и `reservation_ride_id`: в ЛР2 у Scooter были `free/rented/maintenance`, а бронь на 10 минут появилась в ЛР3.
2. Жизненный цикл Ride расширен состояниями `reserved`, `active`, `paused`, `completed_pending_payment`, `paid`, `debt_blocked`, `cancelled`, `rejected`. Для этого время начала становится необязательным до фактического запуска.
3. В ЛР3 указана сниженная ставка паузы, но не её числовое значение. `PAUSE_PRICE_PER_MINUTE` в примере по умолчанию равен 1.00 ₽/мин только как конфигурационная заглушка; уточните значение по требованиям преподавателя.
4. Бронь истекает через 10 минут. `POST /internal/tick` переводит время вперёд и обрабатывает истечение брони и длительность более 12 часов.
5. Платёжный шлюз — in-memory заглушка, не настоящий эквайринг. Данные не переживают перезапуск.

## Тесты

```bash
pytest -q
```

Тесты `test_process.py` покрывают доменный/прикладной процесс. `test_api.py` покрывает HTTP-адаптер и будет запущен после установки requirements. Если Flask недоступен в среде выполнения, HTTP-тесты будут пропущены pytest, а не объявлены успешно пройденными.
